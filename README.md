# 사진 일괄 크기조절 (Batch Photo Resizer)

사진 여러 장과 PDF를 **한 번에 같은 규격으로** 맞춰주는 사내용 도구입니다.
utou 사내에서 쓰려고 만들었습니다.

**실제 주소: <https://utou-photo.netlify.app>**

---

## 한눈에

| | |
|---|---|
| 형태 | **HTML 파일 하나.** 빌드 과정도, 설치도, 서버도 없습니다 |
| 처리 위치 | **전부 브라우저 안에서.** 사진이 서버로 올라가지 않습니다 |
| 비용 | **0원.** 유료 API를 쓰지 않는 것이 이 프로젝트의 기본 전제입니다 |
| 화면 언어 | 한국어 (코드 주석도 한국어) |
| 권장 브라우저 | Chrome, Edge |

## 기능

- 사진 여러 장을 **같은 크기 · 같은 위치**로 일괄 변환 → ZIP 또는 폴더에 바로 저장
- **비율 버튼** (1:1, 4:3, 16:9, 9:16 …) — 긴 쪽 길이를 유지한 채 방향만 바꿉니다
- 맞추는 방식: 전체 보이기(contain) / 꽉 채우기(cover) / 크기만 줄이기(long)
- 3×3 위치 정렬, 여백, 미세 보정
- **피사체 크기 통일** — 사진마다 여백이 달라도 내용물이 같은 크기로 보이게
- 여백 채우기: 자동(사진 테두리 색을 뽑아 씀) / 단색 / 투명 / 흐린 사진
- **PDF → JPG** — 한 쪽이 사진 한 장. 선명도 4단계
- **스크린샷 Ctrl+V 붙여넣기**
- **내 설정** — 설정 한 벌에 이름 붙여 저장 · 불러오기 (브라우저 안에 보관)
- **글자 코드 공유** — 설정을 `UTOU1-…` 로 시작하는 글자로 만들어 카톡·메일로 주고받기

## 파일 구성

```
사진일괄조절.html     ← 본체. 이것 하나가 프로그램 전부입니다 (약 72KB)
preset.json          ← 회사 기본 규격. 같은 폴더에 있으면 자동으로 읽습니다
batch_resize.py      ← 폴더 통째로 돌리는 파이썬 버전 (Pillow 필요, PDF는 미지원)
사용설명서.md         ← 직원용 사용법
배포방법.md           ← 배포 방법 안내

배포용/              ← 이 폴더를 통째로 올리면 배포 끝
  index.html         ← 사진일괄조절.html 의 복사본 (항상 같아야 합니다)
  preset.json
  pdf.min.mjs        ← PDF.js (Apache-2.0)
  pdf.worker.min.mjs ← PDF.js (Apache-2.0)
```

> `사진일괄조절.html` 을 고쳤으면 **반드시** `배포용/index.html` 로 복사하세요.
> `cp 사진일괄조절.html 배포용/index.html`

## 어떻게 돌아가나

전부 `사진일괄조절.html` 안에 있습니다. 바깥에서 가져오는 것은 PDF.js 둘뿐입니다.

**그리는 흐름** — `settings()` 로 화면의 설정을 한 덩어리로 읽고 → `layout()` 이 위치·크기를 계산하고 → `render()` 가 캔버스에 그립니다. 미리보기도 결과물도 같은 길을 씁니다. 그래서 **미리보기에 보이는 것이 저장되는 것과 같습니다.**

**알아둘 만한 부분**

- `layout(iw, ih, s, box)` — 배치 계산의 중심. 여기만 보면 결과를 예측할 수 있습니다
- `subjectBox(bmp)` — 피사체 범위 찾기. 투명 PNG면 알파로, 단색 배경이면 테두리 색과의 거리로 판정
- `autoBgColor(bmp)` — 여백에 쓸 색을 사진 테두리에서 뽑기
- `pdfToPages(entry)` — PDF 한 권을 쪽마다 그림으로. 캔버스에서 `createImageBitmap` 으로 바로 가져오므로 파일로 굽고 다시 읽는 과정이 없습니다
- ZIP은 **직접 만듭니다** (무압축 store + CRC32 + 중앙 디렉터리). 외부 라이브러리를 쓰지 않습니다
- `applySettings(s)` / `PRESET_KEYS` — 설정을 되돌리는 곳. **설정 항목을 늘리면 이 둘만 고치면** 저장·불러오기·코드 공유가 전부 따라옵니다
- `safeSettings(s)` — 남이 보낸 코드를 받을 때 값을 정상 범위로 가둡니다. 바깥에서 들어온 값은 반드시 여기를 거칩니다

**저장 위치** — 설정은 브라우저 `localStorage` 에 들어갑니다 (`photoResizeSettings` = 마지막 설정, `photoResizeMyPresets` = 이름 붙인 설정들). 서버도 로그인도 없어서 **PC마다 따로** 쌓입니다. 그래서 글자 코드 공유 기능이 있습니다.

## 개발 · 시험

빌드가 없으므로 파일을 고치고 브라우저에서 열면 끝입니다. 다만 **PDF 기능은 `file://` 로 열면 동작하지 않습니다** (브라우저가 로컬 파일의 모듈 로딩을 막습니다). PDF까지 보려면 간단한 정적 서버로 띄우세요.

```bash
cd 배포용
python -m http.server 8791     # 또는 npx serve -p 8791
```

그 다음 <http://127.0.0.1:8791> 로 접속합니다.

**시험할 때 걸려 넘어지기 쉬운 것 두 가지** (실제로 당했습니다)

1. **창이 앞에 떠 있어야 합니다.** PDF.js는 화면 갱신 신호(`requestAnimationFrame`)에 맞춰 그리기 때문에, 브라우저 창이 가려져 있으면 PDF 변환이 영영 끝나지 않습니다. 버그가 아닙니다.
2. **"마지막 설정 기억" 때문에 초기화가 잘 안 됩니다.** 페이지를 떠날 때 지금 설정이 자동 저장되므로, `localStorage` 를 지우고 새로고침해도 되살아납니다. 깨끗한 상태로 시험하려면 화면 자체를 `applySettings(기본값)` 으로 되돌리세요.

## 정해둔 것들 (왜 이렇게 만들었는지)

이어받는 사람이 같은 길을 다시 헤매지 않도록 적어 둡니다.

- **유료 서비스를 쓰지 않습니다.** 처음부터의 조건이었습니다.
- **AI 배경제거(누끼)는 뺐습니다.** 테두리를 따라가며 지우는 방식은 배경이 조금만 복잡해도 얼룩이 남았고, 브라우저에서 돌리는 AI 모델은 실제 PC에서 검증하지 못했습니다. 대신 **피사체 크기 통일**을 넣었습니다 — 이미 누끼를 딴 사진들을 나란히 놓을 때 쓰는 기능입니다.
- **로그인·서버가 없습니다.** 그래서 설정이 PC마다 따로 저장되고, 공유는 글자 코드로 합니다.
- **설명은 쉬운 말로.** 「긴 변 기준」, 「확대하지 않기」 같은 표현은 알아듣기 어렵다는 피드백을 받아 그림 버튼과 풀어쓴 문장으로 바꿨습니다. 새 기능을 넣을 때도 같은 기준을 지켜주세요.
- **파일명은 `outName()` 한 곳에서만 만듭니다.** 경로 문자와 제어문자를 거기서 걸러냅니다.
